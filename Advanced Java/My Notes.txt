2) Link Expression

	1. Simple URL
		<a th:href="@{/about}">About</a>

	2. URL with Query Parameters
		<a th:href="@{/search(id=10, name='John')}">Search</a>
	
		Result:
			/search?id=10&name=John
		
	3. URL with Path Variables
		<a th:href="@{/user/{id}(id=${user.id})}">View</a>

		where 
			(id=${user.id}) is value Replacement
		Result:
			/user/5

	4. Form Action URL
		<form th:action="@{/save}" method="post">

------------------------------- Logging (log4j) ------------------------------

-- Logging means recording information about what your application is doing while it runs. These records are called logs.
   - it has three parts 
	1. logger
	2. appender
	3. laylout

-- logging levels (form top to bottom level)

	fatal
		Application cannot continue
	error 
		Something failed
	warn
		Something is not right, but app still works
	info
		Normal flow of the application
	Debug
		What is happening inside the code?

	
   When a logger is created, generally you assign a level. The logger outputs all those messages equal to that level and also to all greater levels than it.

-- log4j.properties vs logback-spring.xml

	Both are logging configuration files, but they belong to different logging frameworks.
	
	log4j.properties
	
		- Used with Log4j (old logging framework).

	logback-spring.xml (used with spring boot)

		- it is used with the application.propertes file 

		- Used with Logback (modern & default in Spring Boot).

		- logback-spring.xml contains logging configuration rules, such as:

			Where logs should go (Appenders)(console, file, etc.)

			How logs should look (format, layout)

			Which logs should appear (log level, )

			Different behavior for different environments (dev / prod)

			Which package should log what (logger)

                  - ex

			<configuration>

    				<appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        				<encoder>
            					<pattern>%d %-5level %logger - %msg%n</pattern>
        				</encoder>
    				</appender>

    				<root level="INFO">
        				<appender-ref ref="CONSOLE"/>
   				 </root>

			</configuration>


		- How to read from application.properties
	
			- Use ${} from application.properties to read the key
			
			- ex     @value("${ }")
				 public String name;

			- use @ConfigurationProperties(prefix = "app")

-- SSO 

	- allows a user to log in once and access multiple applications without logging in again.
	  Example: Login with Google / Facebook.
  	
	- User logs in once and can access multiple features/links within the same application without logging in again

	- Spring Boot uses OAuth 2.0 / OpenID Connect (OIDC) for SSO.


	- SSO Flow (Very Important)
	 	User → Spring Boot App
     		       → Redirect to Identity Provider (Google/Keycloak)
     		       → User logs in
    		       → Identity Provider sends token
     		       → Spring Boot validates token
     		       → User logged in
