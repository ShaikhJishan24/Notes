- AOP (Aspect-oriented programming)

     - Why used AOP
       		- Even if you write the separated class but then also we have to called the methods of that class in Your class hence we used AOP

     - Cross-cutting concerns (Additional logic)
		- code other than the business logic that called Cross-cutting concerns
		- Aspect-Oriented Programming [AOP] helps separate these cross-cutting concerns from the business logic

     - Aspect 
		name of cross-cutting concerns

     - Advice
		implementation of Aspect
	
     - Join point
		- A join point is a well-defined location within the primary code where a concern will crosscut the application. Join points 		  can be method calls, constructor invocations, exception handlers, or other points in the execution of a program.
		- Location (Setters, constructor) where we are doing the Cross cutting concerns

     - Point cut
		Short cut to give the Location (Join cut)	


    1. Before Advice
	before method parameters
		method - method being invoked (e.g. here "multiply")
    		os - arguments to the method ( arg which will be passed to "multiply" method.
    		o - target of the method invocation (object by which "multiply" method has been invoked). May be null ( in case of static 		method)

    2. After returning Advice
	public class LogAfterReturning implements AfterReturningAdvice{
    		public void afterReturning(Object o, Method method, Object[] os, Object o1) throws Throwable {
        		System.out.println("After Normal Return from a method");
		}
	}

	/*

	Parameters:
    		o - the value returned by the method, if any
    		method - method being invoked
    		os - arguments to the method
    		o1 - target of the method invocation. May be null.

	*/
